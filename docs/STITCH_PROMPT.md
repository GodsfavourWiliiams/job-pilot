# Google Stitch design prompt for JobPilot

Design a polished, production quality interface called **JobPilot** for one person managing automatic remote job discovery and applications. Produce complete desktop, tablet, and mobile designs. The result should feel like a premium professional productivity tool, with clear typography, restrained motion, strong information hierarchy, accessible contrast, visible focus states, and believable real data. Avoid the look of a generic recruitment marketplace.

## Product context

JobPilot reads a user's uploaded CV, lets them add desired role titles, searches multiple job sources automatically, filters for remote roles and candidate location, prepares tailored email/CV material, and keeps application forms for manual completion. Email applications can be reviewed or sent automatically when Gmail is connected and the user chooses that preference. Jobs with an unspecified applicant location remain in the queue with a clear **location needs verification** warning; they cannot auto-send. Job source failures and filter reasons must be visible. Search can run every 10, 20, 30, or 60 minutes even while the dashboard is closed, provided the local app is running. Do not show fake success counts or imply every source always works.

## Visual direction

- Keep the existing brand direction but elevate the layout: primary teal `#087F79`, deep navy `#142336`, dark sidebar `#122539`, canvas `#F6F8F8`, white surfaces, soft teal `#E6F5F2`, bright accent `#24B4A7`, text `#1B2B3B`, muted text `#718193`, borders `#E8EDF0`.
- Use Manrope for headings and DM Sans for body, with a good system font fallback. Rounded corners around 10–14px, subtle shadows, generous but efficient spacing, and crisp icons. The UI should feel credible and calm rather than playful or empty.
- Desktop: compact fixed sidebar, top bar, maximum content width, useful two column areas where appropriate. Mobile: a deliberate bottom navigation or compact menu, stacked cards, sticky primary action where helpful, full width form controls, no horizontal overflow. Show 1440px desktop, 768px tablet, and 390px mobile variants for key screens.
- Establish a consistent visual language for page headings, buttons, status chips, source badges, scan status strips, summary cards, job cards, search/filter bars, detail panels, form fields, toggles, logs, alerts, empty states, loading states, notifications, and confirmation dialogs.

## Navigation and screens

1. **Onboarding, four steps.** Welcome and what automation does; CV PDF upload with extraction progress and an editable professional title/skills preview; candidate details (name, email, country, time zone from a searchable list, preferred remote role titles and optional locations); automation choices (10/20/30/60 minute scan, career levels inferred from CV but editable, full time/part time/contract, review emails toggle, daily email cap, Gmail connection). End with a clear setup review and “Start searching” state. Make it obvious that every choice can be edited later. Use sample profile information as illustrative content, not fixed labels.

2. **Application queue.** Retain the current useful list/card idea but make it richer and visually sharper. At the top show a live scan strip: searching/idle/paused state, pulse or progress when running, last run, next check, interval, and outcome summary (fetched, matched, added, errors). Show counts for needs review, manual forms, email ready, and completed. Add search plus status, source, location verification, and sort controls; allow a compact/mobile filter sheet. Each job card shows role, company, location, remote eligibility confidence, employment type, source, posted date, match score, and action state. Distinguish verified worldwide/Nigeria eligible from “remote, applicant country unknown.” Clicking opens a detailed right drawer on desktop and full-screen sheet on mobile with original link, full description, match explanation, requirements, location warning, tailored email, tailored CV preview/download, and actions: open application form, review/send email when available, mark applied, and **Not a fit**. For Not a fit, ask a reason (not actually remote, location restriction, closed listing, wrong role, duplicate, other) plus optional note.

3. **History.** A distinct timeline/table hybrid for applied, sent, dismissed, and failed outcomes. Give it search, date range, status, source, and sort controls. Show application method, send/submission timestamp, company, role, and outcome; expand rows for email contents, original link, CV version, dismissal reason/note, and any retryable error. Design a useful empty state.

4. **Source activity.** A dedicated page, not buried in Preferences. Make hundreds of sources manageable with search, status filters, and clear grouping. Each source row shows name, enabled toggle, health state, last attempt, last success, fetched count, matched count, filtered count, next eligible check, and the latest error/warning. Include details for searches and pages inspected, with honest states such as access denied, verification challenge, connection needed, or no results. Add a run log with timestamp, duration, trigger (automatic/manual), fetched/matched/new totals, and expandable per-source metrics and filter reasons. Show a clear next scheduled check and running indicator. Include sources such as RemoteJobs.org, Himalayas, We Work Remotely, Remote OK, Jobicy, Remotive, Google web search, LinkedIn public jobs, Bluesky, X, and company boards as sample data; do not imply they all succeeded.

5. **Profile & CV.** Make this feel like a professional identity workspace instead of a plain settings form. Show editable name, email, country, time zone, professional title, role interests, skill tags inferred from the CV, uploaded PDF card with replace/download actions, extraction preview, and a clear explanation of which details drive search and draft generation. Include save feedback and validation states.

6. **Preferences.** A clear automation control center using grouped sections: automatic search on/off and 10/20/30/60 minute interval; role titles and optional search terms; inferred career levels with manual override; employment types; remote location/country preferences; review emails before sending on/off; daily send cap; browser notification preference; Gmail connection status with Connect/Disconnect action. Explain that turning review off permits eligible email applications to send automatically, while form applications still require manual completion. Keep source switches on Source activity, with a link from Preferences.

7. **Gmail connection and email review.** Design the disconnected, connecting, connected, expired, and error states. For a pending email, show recipient, subject, message, tailored CV attachment, source listing, eligibility checks, and a Send action. Show a meaningful confirmation and sent state. Make it clear when Gmail has not yet been connected.

## Interaction and design deliverables

- Make all controls, tables, filters, drawers, and forms coherent across pages. Show hover, focus, disabled, loading, success, and error states, plus accessible labels and high contrast status colors. Use realistic example counts and timestamps.
- Preserve honest product language: “source checked,” “location to verify,” “form to complete,” “email ready,” “last run,” “next check,” and “not a fit.” The app searches automatically; “Find jobs” is a manual override, not the primary workflow.
- Deliver complete screen designs, responsive variants, and a visual inventory of recurring interface elements for every screen above. Focus on appearance and user flow, not code or technical architecture.
