# Implementation review

## Sources and requests

JobPilot currently reads **thirteen source families**. The server fetches JSON feeds, RSS, public job-search HTML, and linked pages from social posts. It extracts `JobPosting` JSON-LD from accessible remote career pages. Google can return Indeed, LinkedIn, or Glassdoor links, but those pages only enter the queue when their HTML can be fetched and contains structured remote job data. A challenge, HTTP error, or missing structured data is visible in source details and can yield zero jobs.

| Board | Request | Scope | Frequency |
| --- | --- | --- | --- |
| Himalayas | `GET https://himalayas.app/jobs/api/search?q=<role>&sort=recent&page=<n>` | Five recent result pages for each CV-expanded role query, up to 20 listings per page | Daily cache; at most daily |
| Remotive | `GET https://remotive.com/api/remote-jobs?category=software-dev&limit=250` | Up to 250 recent software development listings, then local title filtering | Per-source cooldown |
| Jobicy | `GET https://jobicy.com/api/jobs?industry=engineering&count=200[&cursor=…]` | Up to five cursor pages of 200 recent engineering listings, then local filtering | Per-source cooldown |
| Remote OK | `GET https://remoteok.com/api` | Public remote feed, then local filtering | At most every ten minutes |
| Greenhouse | `GET https://boards-api.greenhouse.io/v1/boards/<token>/jobs?content=true` | Company catalog: Canonical, GitLab, Remote, Moniepoint; only explicitly remote locations | At most every 30 minutes |
| Google web search | `GET https://www.google.com/search?q=remote+<role>+jobs+apply` | Up to seven CV-expanded role searches, covering the current frontend, React, Next.js, and JavaScript variants; inspect at most 20 result pages and extract remote `JobPosting` JSON-LD | At most hourly |
| Arbeitnow | `GET https://www.arbeitnow.com/api/job-board-api?page=<n>` | Three recent pages; remote flag required | At most every ten minutes |
| We Work Remotely | Three official category RSS feeds | Front-end, full-stack, and programming jobs; deduplicated by listing URL | At most every ten minutes |
| The Muse | `GET https://www.themuse.com/api/public/jobs?location=Flexible%20%2F%20Remote&page=<n>` | Up to ten pages of remote/flexible listings, then local title and country review | At most hourly |
| RemoteJobs.org | `GET https://remotejobs.org/api/v1/jobs?category=programming&q=<skill>&limit=50&offset=<n>` | Up to three 50-job pages each for five distinct CV-expanded specialties; deduplicated by listing ID | At most every ten minutes |
| LinkedIn public jobs | `GET https://www.linkedin.com/jobs/search/?keywords=remote+<skill>&location=<place>&f_WT=2` | Nigeria and worldwide searches across four CV-expanded specialties; inspect up to 20 job pages and keep structured remote postings | At most hourly |
| Bluesky | `GET https://public.api.bsky.app/xrpc/app.bsky.feed.searchPosts?q=<skill>+remote+hiring` | Search recent hiring posts, follow up to 20 external links, keep structured remote postings | At most every 30 minutes |
| X | `GET https://api.x.com/2/tweets/search/recent?query=<skill>...` | Search recent hiring posts, follow up to 20 external links, keep structured remote postings; requires `X_BEARER_TOKEN` | At most hourly |

The exact endpoints, enabled flags, fallback query list, role-focus expansions, page count, category, limit, and schedule are in [`config/search.json`](../config/search.json). The user can enter desired roles in Preferences, such as `frontend`. The effective searches combine that intent with skills found in the CV: a frontend focus adds React, Next.js, and JavaScript title variants when those skills appear in the CV. If no desired role is entered, a supported focus can be inferred from the CV; otherwise the configured fallback queries apply. Himalayas supports a free API key through `HIMALAYAS_API_KEY`; an anonymous request also works. Remotive does not require a key.

Himalayas requires using its `applicationLink` for the Apply action and visible source credit. Remotive, Jobicy, Remote OK, and RemoteJobs.org require source attribution and links back. The dashboard displays each source and original listing. Remotive says its public API listings are delayed by 24 hours and recommends no more than four fetches per day. Himalayas says its API data is refreshed every 24 hours. RemoteJobs.org advises staying below 200 requests per hour; the configured maximum is 90 per hour when a scan runs every ten minutes. Per-source cooldowns honor these limits while the scheduler checks on the user-selected interval. ## Processing path

1. [`lib/sources/index.ts`](../lib/sources/index.ts) registers the thirteen source adapters. Each adapter builds its own request from the active config; [`lib/feeds.ts`](../lib/feeds.ts) runs enabled adapters concurrently. A failure from one source does not discard another source's results. Every attempt saves fetch and match counts, filter reasons, and errors in `sourceRuns`, visible in Source activity. Search adapters also report how many linked pages they inspected.
2. [`lib/normalise-source.ts`](../lib/normalise-source.ts) converts different API field names into one internal job shape. Himalayas country objects become readable locations, and API timestamps become dates. Unknown location stays unknown and enters manual review; it cannot trigger automatic email. Unknown employment is also retained for review. The [Google adapter](../lib/sources/google.ts) extracts only structured remote postings, and the [RSS adapter](../lib/sources/weworkremotely.ts) parses public feeds into the same internal shape.
3. [`lib/match.ts`](../lib/match.ts) classifies title and structured seniority values with configured level terms, then checks the user's saved accepted levels. It rejects explicitly excluded employment types and locations that do not permit the candidate's country. Source timezone restrictions are shown as review notes rather than hiding the job. Unspecified levels remain visible for manual review and cannot auto-send email. For Nigeria, the configured aliases include Nigeria, NG, Africa, and EMEA, plus UTC+1. The text matcher is conservative and can miss ambiguous listings. It scores remaining jobs using title and CV/description overlap. The score is a heuristic, not proof of eligibility.
4. [`lib/service.ts`](../lib/service.ts) deduplicates by source ID and company/title, prepares an email and role-specific CV from the saved resume text, and saves a queue entry. A Remotive listing with a `mailto:` link or explicit application email can be email-ready. Himalayas listings use their `applicationLink` for applications, as its API terms require; they stay as manual application tasks unless that link itself is `mailto:`. Other listings become form tasks for manual submission. Email is only sent automatically when Gmail is connected, review is disabled, and the daily cap permits it.

Coverage is limited by the configured feeds, four Greenhouse company boards, Google result ranking, and the number of pages inspected. It is not a census of hundreds of boards. Each source has a separate cooldown. Listings may close early, and the app does not currently verify each listing's live status before showing it or sending an email. A manual scan uses the same per-source cooldowns as automatic checks. See [backend expansion plan](BACKEND_PLAN.md) for the larger catalog and onboarding path.

## Configuration and persistence

[`lib/config.ts`](../lib/config.ts) is the settings boundary. Today it loads `config/search.json` from disk for every scan and dashboard state request. Later it can load the same `SearchConfig` shape from an authenticated API or database. The UI's desired-role interests are stored in preferences; an empty list means infer a supported focus from the CV and then fall back to configured queries. The current app is single-user, so that user is the local installation.

[`lib/store.ts`](../lib/store.ts) stores the profile, preferences, queue, statuses, last scan timestamp, recent scan logs, source runs, and Gmail connection metadata in `data/state.json`. Updates are serialized and written through a temporary file plus rename. These values do not depend on `localStorage` or the browser session. The dashboard shows scheduled scan activity and recent runs, while queue and history allow search, filtering, and sorting. Dismissed jobs retain a selected reason and optional note. [`lib/gmail.ts`](../lib/gmail.ts) stores the OAuth refresh token separately in `data/gmail-token.enc`, encrypted with the local `TOKEN_ENCRYPTION_KEY`; the Gmail password is never stored. Both data files are excluded from git.

[`instrumentation.ts`](../instrumentation.ts) conditionally loads the Node-only scheduler in [`instrumentation-node.ts`](../instrumentation-node.ts), keeping filesystem and crypto modules out of browser and Edge bundles. The dashboard state route also ensures the scheduler is running after a dev reload. The scheduler checks every minute whether a scan is due. A scan is due after the selected 10, 20, 30, or 60 minutes when automatic search is enabled and the CV has text. Transient source failures retry after at most ten minutes; HTTP 401/403/429 and consent/challenge failures back off for at least six hours. Successful sources retain their configured cooldowns. The optional [`scripts/background.mjs`](../scripts/background.mjs) installer runs the built local server as a macOS LaunchAgent at login, allowing the interval to continue with the browser closed. This is local automation while the Mac is awake and logged in, not a hosted always-on service. Browser notifications need the dashboard open. Phone push notifications are not yet implemented.

## Validation and current limits

`npm test` covers matching, email detection, draft grounding, source normalization, Google result parsing and page extraction, RSS parsing, and per-source adapters. `npm run typecheck` and `npm run build` cover TypeScript and the production bundle. In the latest live scan on 2026-10-21, RemoteJobs.org returned 486 listings and LinkedIn returned 13 structured postings; the matcher accepted 25 and added 24 candidates before an additional false-positive review hid ten. The visible queue then contained 19 jobs, many still marked as needing applicant-location verification. Google reached a consent/challenge redirect and produced no jobs; The Muse returned HTTP 403; Bluesky search returned HTTP 403; X cannot search until `X_BEARER_TOKEN` is configured. These outcomes are recorded in Source activity. The development shell cannot resolve external hosts or call the running app directly, so the live scan was triggered and inspected in the browser. Review each original listing before relying on automatic applications.
